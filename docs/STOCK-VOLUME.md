# 个股分析

在自选股上右键选择「个股分析」，打开独立窗口。目前支持沪深 A 股股票，不包含 ETF、指数、北交所、港股和美股。同时分析一只股票，选择另一只会取消之前的请求。窗口展示成交量分析，以及该股票公开披露的汇金、社保基金持仓。

## 公开持仓

窗口底部展示该股票最新报告期的前十大流通股东中出现的中央汇金、全国社保基金持股，并列出每个持有人的最近披露持股数、占流通股比例和较上一报告期的变化。最多查询最近 200 条股东记录；未出现不代表没有持仓。打开窗口时优先读取本地按股票缓存；缓存超过 24 小时或手动刷新时请求一次，避免每次开窗都下载完整股东数据。持仓以公开披露为准，存在滞后，公开数据不提供机构买入成本，因此不估算盈亏。

## 展示与口径

- 柱图可切换「分类成交量」「净买 / 净卖」，支持悬停读数和可展开的分钟数据表，成交量单位为手；不再提供独立的「总成交量」模式。
- 「净买 / 净卖」按分钟分别计算大、中、小额的主动买入估额减主动卖出估额，单位万元。三类沿用分类成交量的蓝、橙、绿颜色；各类正净额在零轴上方堆叠，负净额在下方堆叠，正负使用对称刻度，并按两侧堆叠总额确定范围。不同类别相互抵消时仍分别展示；悬停读数和分钟表列出三类净额及合计。中性成交不计入净额。没有完整分类的分钟（部分分类、无法对账的未分类分钟）以零轴处的灰纹缺失标记表示，表格和读数显示 `—`，不把缺失当成零。
- 东方财富明细估额 = 明细价格 × 成交手数 × 100 股；腾讯采用源接口提供的成交额。大额 ≥ 100 万元，中额为 10 万至不足 100 万元，小额 < 10 万元。
- 分类统计包含成交手数、主动买入估额、主动卖出估额、中性估额、买卖净估额，金额单位万元人民币。方向采用源字段（1 卖出、2 买入、4 中性），净额为买入减卖出。
- **公开明细可能合并多笔成交。分类表示明细记录的估算规模，不表示原始委托大小，也不识别机构、量化或散户身份。** 明细价格是该记录的价格，不保证是合并成交的量加权均价，因此金额仅为估算。
- 不移植 anlan-zen 的身份式启发标签、市场先验或概率拆分历史。第一版复用其明细分类与分钟聚合思路，使用可解释的金额分档。

## 数据源与对账

每轮经现有 `HTTPClient` 并发获取分钟和明细，遵循 App 代理设置及禁止本地 HTTP 缓存的策略。优先东方财富，任一路请求失败、响应无效或没有数据时，仅该路改用腾讯。两路均成功后才发布整份结果，底部标明实际来源。取消请求不会触发备用切换：

| 请求 | 参数 | 用途 |
| --- | --- | --- |
| `push2.eastmoney.com/api/qt/stock/trends2/get` | `ndays=1`，`fields2=f51,f52,f53,f54,f55,f56,f57,f58` | 带交易日期的分钟序列，取 f56 成交手数 |
| `push2.eastmoney.com/api/qt/stock/details/get` | `pos=-100000`、`iscca=1`，`fields2=f51,f52,f53,f54,f55` | 尽量请求当天完整明细快照；取时间、价格、手数、方向 |

腾讯备用接口直接以 Swift 接入，来源为 anlan-zen 使用的 AkShare 函数对应的上游，无 Python / AkShare 运行依赖：

| 请求 | 用途 |
| --- | --- |
| `stock.gtimg.cn/data/index.php?appn=detail&action=info&c=sz000001` | 提供明细交易日期及分页列表 |
| 同路径，`action=data&p=N` | 按页获取时间、价格、手数、成交额和 B/S/M 方向；最多 4 路并发 |
| `web.ifzq.gtimg.cn/appstock/app/minute/query?code=sz000001` | 带日期的分钟累计手数，差分成分钟量；忽略 13:00 及盘后点，缺口不能分配给下一分钟 |

腾讯已完成页按股票和交易日期缓存在内存中，尾页每轮重拉；切换股票或跨日清空。缺页或错误页码使整轮失败，不发布半份快照。使用源记录序号去重，冲突序号报错。交易日期与分钟日期不同则拒绝合并。

`pos` 是请求范围，不是完整性保证。东方财富明细行按股票和交易日在窗口内跨轮合并后再对账，滚动窗口不会丢掉本轮之外的历史行；同一天内分钟结果也与上一轮合并，新的快照只会补上或更新已对账的分钟，不会因为某一路变慢、被截断或改用备用源而删掉上一轮已分类的分钟。跨交易日或换股时缓存清空，新的一天从头开始。不同来源的明细不混合；两家的买卖方向标记可能不同，切换来源后的净额不可假定完全可比。

时间轴采用上海时区，交易日期取分钟接口。09:25 实际集合竞价归入 09:30；更早的试撮合报价排除。09:30:00–09:30:59 对应 09:31 分钟，13:00 对应 13:01，11:30:00 和 15:00:00 分别归入上午末分钟和收盘分钟；午休和盘后明细不计入。

只统计两个快照共有的已完成分钟，排除仍变动的尾分钟，15:00 收盘分钟允许保留。两家接口的统计口径并不完全一致，逐分钟按「精确 / 部分 / 估算 / 未分类」四级对账，尽量保留真实观测，又绝不凭空造量：

- **精确**：明细量与分钟量相差不超过 max(2 手, 0.1%)，视为舍入一致，把明细构成按分钟量微调后分类。
- **部分**：明细量少于分钟量（明细被截断或来源统计范围更窄），直接分类已观测的记录，差额显式计入「未知」，不缩放、不推测剩余方向构成。该分钟不发布净额。
- **估算**：明细量略多于分钟量但不超过 2%，按比例缩放回分钟量；若该分钟没有明细或明细明显超量，但前后共 3 个已完成分钟构成的窗口能在 max(2 手, 1%) 内对账，则借用窗口的类别构成、按本分钟总量缩放后归类。窗口只修正边界归属，不新增总量。
- **未分类**：以上条件都不满足，该分钟不发布分类和净额，只保留分钟总量。

分类覆盖率 = 已分类手数 / 所示分钟总手数。分钟表新增「置信度」列，悬停读数带同样标记，汇总下方注明部分分类和窗口估算的分钟数。总量、分类统计及图表使用同一个时间范围；汇总的手数和金额按已观测记录累计，存在部分分类分钟时是下界。

东方财富明细接口没有交易日期字段，腾讯则由分页元信息校验日期。腾讯在 11:30 / 15:00 后数秒报告的收盘记录归入该时段末分钟。对账是两个序列的一致性检查，不是独立交易所级的逐笔完整性证明。源端已合并的成交不能拆回原始逐笔，也不能提供任意历史日期回放。

## 刷新与错误

窗口打开且缓存超过 20 秒时加载一次；随后可见且 A 股开市时每 60 秒刷新。关闭、最小化或完全遮挡时取消请求和轮询。支持暂停和手动刷新，同一时刻最多一轮；暂停时仍可手动刷新。

东方财富请求共用 250 毫秒启动间隔的门控；瞬时传输失败或 5xx 重试一次（300–700 毫秒抖动），429 和数据无效不重试、直接换腾讯。分钟序列没有前进时自动轮询跳过明细请求，直接复用当天已合并的结果；手动刷新始终重新请求明细。整轮失败时自动轮询按 60 → 120 → 240 → 480 → 600 秒退避，任一轮成功即恢复 60 秒。

任一接口失败保留上次成功的整份数据和更新时间，显示错误，不把失败当成零成交量。首次失败显示错误和刷新入口。单请求超时 15 秒，无持久化历史、Python 或 AkShare 运行依赖。

## 验证记录

2026-11-12 对 `0.000001`（平安银行）读取到 3,868 条含集合竞价试撮合报价的明细。排除试撮合、按分钟结束时间对齐后，抽查的 200 个已完成分钟逐分钟量完全一致，合计 857,222 手。当天批量请求上海标的 `1.600519` 多次返回 HTTP 502，另一上海标的也出现 502/超时；不能由本次结果声称所有股票或全天候接口稳定可用。

同日对腾讯整日分页及正常交易时段分钟数据验证：贵州茅台 58 页、4,040 条记录，241 分钟中 225 分钟量完全一致，明细合计 32,371 手、分钟合计 32,373 手；平安银行 65 页、4,482 条记录，236/241 分钟完全一致，分别合计 1,082,720 和 1,082,721 手。部分分钟存在少量手数差异，原因未独立验证；这些分钟现在按上述容差、部分分类或相邻窗口归类，超出范围的仍保持未分类。

2026-11-24 开盘时段对平安银行复测：push2 常常 302 到 push2delay 后返回 502 或超时（分钟 7 次仅 1 次成功，明细 5 次中 2 次成功），腾讯接口稳定。已完成的 44 个分钟里，东方财富分钟 + 东方财富明细 44/44 严格相等；东方财富分钟 + 腾讯明细仅 33/44，腾讯分钟 + 腾讯明细 30/44。该比例按严格相等统计，尚未按新分级重新实测；两路独立换源会让分类覆盖率在 ~68%–100% 之间跳动，因此跨轮合并和只向前发布是必要的。
